# 本地视觉核对流程(双主题 / 多分页截图)

改完样式或布局后,用这套流程可以在**不开浏览器手工点**的情况下拿到两套主题、三个分页的真实渲染截图,
并且能精确裁掉底部空白、直接更新 README 里的截图。

全程只依赖本机已装的 Chrome,不需要额外安装 Playwright / Puppeteer / Chromium。

## 1. 起开发服务器

```bash
npm run dev        # 默认 http://localhost:5173
```

## 2. 准备示例数据(可选,建议做)

图表、历史列表、外键统计都需要有数据才能看出问题,而真实数据在你自己浏览器的 IndexedDB 里,
无头浏览器是另一个 profile,读不到。做法是在项目根目录临时放一个 `seed.html`
(放在根目录而不是 `public/`,这样不会被构建进 `dist/`),让它在同源下打开 IndexedDB 写入示例数据:

```js
// 库名 / 版本 / 表名 / 主键必须与 src/hooks/useIndexedDB.ts 保持一致
const req = indexedDB.open('cycling-dashboard', 3)
req.onupgradeneeded = () => {
  const db = req.result
  if (!db.objectStoreNames.contains('rides')) db.createObjectStore('rides', { keyPath: 'id' })
  if (!db.objectStoreNames.contains('bikes')) db.createObjectStore('bikes', { keyPath: 'id' })
  if (!db.objectStoreNames.contains('days')) db.createObjectStore('days', { keyPath: 'id' })
}
req.onsuccess = () => {
  const tx = req.result.transaction(['rides', 'bikes', 'days'], 'readwrite')
  for (const r of sampleRides) tx.objectStore('rides').put(r)   // 字段见 src/types.ts 的 RideRecord
  for (const b of sampleBikes) tx.objectStore('bikes').put(b)
  tx.oncomplete = () => { document.title = 'seeded' }
}
```

想让图表好看,示例数据要覆盖这些点:记录日期分散在最近一个月(趋势图)、
`scores` 有高低差异(档位色带)、`track` 是闭合环线且带 `ele`(地图与海拔曲线)、
`speedSeries` 有几十个点(速度曲线)、至少两辆车且其中一辆外胎接近寿命(角标与提醒)。

同时可以顺便写入主题偏好(应用读的就是这个 key):

```js
localStorage.setItem('cycling-dashboard:theme', theme)   // 'dark' | 'light'
```

> 注意:`seed.html` 只是本地核对用的临时文件,核对完请删除,避免误当成产品功能。

## 3. 截图

固定 Chrome profile 目录,这样 IndexedDB 与 localStorage 在多次调用之间能保留:

```bash
CHROME="/c/Program Files/Google/Chrome/Application/chrome.exe"
PROFILE='C:\Users\<你>\AppData\Local\Temp\cycling-profile'
SHOT='C:\Users\<你>\AppData\Local\Temp\cycling-shots'

# 3.1 播种(顺便设定主题)
"$CHROME" --headless=new --disable-gpu --no-first-run --user-data-dir="$PROFILE" \
  --virtual-time-budget=8000 --dump-dom "http://localhost:5173/seed.html?theme=dark" >/dev/null

# 3.2 按分页截图(hash 路由可以直接深链)
for t in record dashboard bikes; do
  "$CHROME" --headless=new --disable-gpu --hide-scrollbars --no-first-run \
    --user-data-dir="$PROFILE" --window-size=1440,2800 --virtual-time-budget=12000 \
    --screenshot="$SHOT\\dark-$t.png" "http://localhost:5173/#/$t"
done
```

要点:

- `--window-size` 的高度给足(2800),让整页都能被渲染,后面再裁掉空白。
- `--virtual-time-budget` 太短会导致 IndexedDB 还没读完就截图,页面停在「加载中…」。
  如果截图异常,先加大这个值再判断是不是真的 bug。
- 换主题要**重新播种**(改 localStorage 后必须重新导航),同一个窗口内不会重新读初值。

## 4. 裁掉空白并更新 README 截图

`--screenshot` 只能截窗口大小,底部会留出页面底色。用 PIL 从下往上找第一行内容,裁掉空白行:

```python
from PIL import Image
im = Image.open(src).convert('RGB')
w, h = im.size
px = im.load()
bg = (11, 16, 32)          # 深色 --page;#f4f6fa 为浅色主题

def row_is_bg(y):
    step = max(1, w // 60)
    return all(
        abs(px[x, y][0] - bg[0]) + abs(px[x, y][1] - bg[1]) + abs(px[x, y][2] - bg[2]) <= 12
        for x in range(4, w - 4, step)
    )

bottom = h - 1
while bottom > 100 and row_is_bg(bottom):
    bottom -= 1
im.crop((0, 0, w, bottom + 40)).save(dst, optimize=True)
```

README 引用的四张图对应关系:

| 文件 | 内容 | 主题 |
|---|---|---|
| `docs/screenshots/01-record.png` | 记录页(打卡 + 录入 + 评分) | 深色 |
| `docs/screenshots/02-dashboard.png` | 看板页(趋势/曲线/地图/雷达/历史) | 深色 |
| `docs/screenshots/03-bikes.png` | 单车与轮胎 | 深色 |
| `docs/screenshots/04-light-mode.png` | 看板页 | 浅色 |

## 5. 收尾

```bash
rm seed.html                     # 删掉临时种子页
```

并确认 `5173` 端口上自己起的 `vite` 进程已退出(不要在他人已有服务上误杀进程):

```powershell
Get-NetTCPConnection -LocalPort 5173 -State Listen |
  ForEach-Object { (Get-CimInstance Win32_Process -Filter "ProcessId = $($_.OwningProcess)").CommandLine }
```

## 附:用过的坑

- Windows 上 Chrome 不认 MSYS 路径,`--screenshot` 必须给 `C:\...\x.png` 这种 Windows 路径。
- 用 `--default-background-color=00000000` 可以把 SVG 渲染成透明底 PNG,
  用来生成图标很方便(本项目的 `apple-touch-icon.png`、`icon-maskable.png` 就是这么产的)。
- 无头截图只能看静态渲染结果,点击/交互仍需 `agent-browser` 之类的工具或人工核对。
